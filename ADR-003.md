# ADR-003: Flujo de Recepción y Topología de Colas en RabbitMQ
**Estado:** Aceptado

## Contexto
El procesamiento síncrono del webhook de Telegram arriesga timeouts y pérdida de datos ante ráfagas intensas de tráfico.

## Alternativas consideradas
* Procesamiento síncrono tradicional.
* Desacoplamiento asíncrono mediante RabbitMQ.

## Decisión
Se eligió **RabbitMQ** para aislar la recepción del mensaje del almacenamiento físico. Se configuró un Exchange `Direct` (`telegram.updates`) vinculado mediante la routing key `telegram.message.received` a una cola persistente (`telegram.received_messages`).

## Consecuencias
* **Ganancia:** Alta resiliencia; si la base de datos se detiene, las conversaciones quedan a salvo en el broker de mensajería.
* **Resignación:** Mayor complejidad en el stack de infraestructura dentro de Docker Compose.
